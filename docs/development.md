# Developing webgd

See [architecture.md](architecture.md) for the component design and [wire-format.md](wire-format.md) for the capture format. Usage is in [user-guide.md](user-guide.md).

## Prerequisites

- Rust 1.99+ (edition 2024).
- `rustup target add wasm32-unknown-unknown`
- `cargo install wasm-bindgen-cli --version 0.2.130 --locked` — must equal the `wasm-bindgen = "=0.2.130"` pin; `cargo xtask build` checks `wasm-bindgen --version` and exits if it differs.
- Node.js, for `tools/gen-wire-fixture.cjs`.
- Chrome 121 or newer.

## Layout

| Path | Contents |
|---|---|
| `crates/webgd-core` | Capture model, wire decoder (`wire.rs`), call labels (`display.rs`), pixel decoding (`pixels.rs`), vertex/index decoding and primitive assembly (`geometry.rs`), pure trackers `track/{commands,gl,gpu,resources,revisions}.rs`. Native-testable. |
| `crates/webgd-analysis` | WGSL (naga) and GLSL (glsl-lang) static analysis; cost model constants in `model.rs`; vertex→compute transform and GLSL vertex output discovery in `vsxform.rs`. Native-testable. |
| `crates/webgd-replay` | wasm only. Replay engine (`engine.rs`), JS helpers (`js.rs`), value conversion (`value.rs`), GL snapshot/formats/uniforms/inspection (`gl/`), GPU snapshot/inspection (`gpu/`), draw geometry extraction (`geometry.rs`), trace runner (`trace.rs`). |
| `crates/webgd-ui` | wasm cdylib. eframe 0.36 + egui_dock 0.21 on wgpu. `app.rs` (menu bar, status bar, workspaces and their dock layouts), `state.rs` (`AppState`, `Tab`, `Workspace`, loaded capture with resource rows and revision histories), `widgets.rs` (shared colors and widgets), `port.rs` (extension port client), `files.rs` (open/save), `replay_queue.rs` (replay scheduling), `panels/` (see below). |
| `crates/webgd-cli` | Native binary `webgd`: Markdown text export of a `.webgd` capture (`webgd capture`, `webgd help`). |
| `xtask` | Build orchestration. |
| `extension/` | `manifest.json`, `hook.js` (MAIN world, capture), `bridge.js` (isolated world, transport), `background.js` (opens the UI tab). `extension/ui/` is build output and gitignored. |
| `web/` | `index.html`, `main.js` host page templates copied into `extension/ui/`. |
| `tests/pages/` | Fixture pages `webgl2.html`, `webgpu.html`, shared `common.js`. |
| `tests/fixtures/sample.wire` | Wire fixture generated by `tools/gen-wire-fixture.cjs`. |

UI panels in `crates/webgd-ui/src/panels/`: `capture.rs` (Capture), `commands.rs` (Events), `scrubber.rs` (Scrubber), `inspect.rs` (Render Targets, API Inspector), `geometry.rs` (Geometry), `resources.rs` (Resources), `viewer.rs` (Resource Viewer and Revisions panel), `trace.rs` (GPU Trace), `log.rs` (Log).

## Build

```sh
cargo xtask build            # debug
cargo xtask build --release
```

`xtask` runs `cargo build -p webgd-ui --target wasm32-unknown-unknown`, then `wasm-bindgen --target web --no-typescript --out-dir extension/ui --out-name webgd_ui`, then copies `web/index.html` and `web/main.js`. Output: `extension/ui/{index.html,main.js,webgd_ui.js,webgd_ui_bg.wasm}`. After rebuilding, click reload on the extension in `chrome://extensions` and reopen the webgd tab.

## Tests and checks

```sh
cargo test
cargo clippy -p webgd-replay -p webgd-ui --target wasm32-unknown-unknown
node tools/gen-wire-fixture.cjs && git diff --exit-code tests/fixtures/sample.wire
cargo run -p webgd-cli -- capture tests/fixtures/sample.wire   # Markdown export to stdout
```

`cargo test` runs only the native `default-members` (`webgd-core`, `webgd-analysis`, `webgd-cli`, `xtask`):

- `crates/webgd-core/tests/wire.rs` — decodes `sample.wire` and checks sections, method names, blob bytes and labels; every truncated prefix returns `Truncated` without panicking.
- `crates/webgd-core/tests/pixels.rs` — f16 and rg11b10 decoding, sRGB passthrough, range mapping, channel masking.
- `crates/webgd-core/tests/track.rs` — command tree, resource list and GPU state tracking on hand-built captures.
- `crates/webgd-core/tests/revisions.rs` — revision histories: access classification, per-resource numbering, view→texture attribution, setup vs frame sections, `revision_at`.
- `crates/webgd-core/tests/geometry.rs` — attribute format decoding, index decoding, draw vertex ids, vertex fetch and primitive assembly (13 tests).
- `crates/webgd-core/tests/export.rs` — Markdown capture and trace exports (`capture_markdown`, `trace_markdown`): section contents, options, row limits, deterministic output.
- `crates/webgd-analysis/tests/stats.rs` — cost model cases for WGSL and GLSL ES 3.00 (ALU, loops, branches, texture samples, workgroup memory and occupancy).
- `crates/webgd-analysis/tests/vsxform.rs` — WGSL vertex→compute transform (IO contract, bind group placement, output order, rejected IO) and GLSL vertex output discovery (7 tests).
- `crates/webgd-analysis/tests/glsl_preprocess.rs` — GLSL preprocessing in `glsl_stats` and `glsl_vertex_outputs`: three.js-style `#ifdef`/`#else` branches, object and function-like macros, `#if` expressions, `GL_ES`/`__VERSION__`, unknown extensions, and parse error lines (5 tests).

`webgd-replay` and `webgd-ui` only build for wasm32, so they are covered by clippy and the manual checklist below.

### Fixture rule

`extension/hook.js` (`WireWriter`, exported for Node) and `crates/webgd-core/src/wire.rs` must agree byte for byte. Any change to the encoder or decoder must regenerate the fixture with `node tools/gen-wire-fixture.cjs`, update `crates/webgd-core/tests/wire.rs` if the expected contents change, and bump the format version if old files can no longer be read. CI-style check: the regeneration command above must leave no diff.

## Fixture pages

```sh
python3 -m http.server 8000 --directory tests/pages
```

- `http://localhost:8000/webgl2.html` — offscreen RGBA16F cube pass with UBO, VAO, Uint16 indices, checker texture and sampler, then a composite pass to the default framebuffer sampling a 4×4 LUMINANCE texture. Wrapped in `Offscreen` / `Composite` markers.
- `http://localhost:8000/webgpu.html` — the same scene in WebGPU: rgba16float offscreen target with depth24plus, mappedAtCreation buffers, a per-frame mapped staging buffer copied into the uniform buffer, debug groups `Offscreen` (with an `insertDebugMarker`), `Compute` and `Composite`.

## Manual end-to-end checklist

1. `cargo xtask build`; load `extension/` unpacked; open `http://localhost:8000/webgpu.html` (reload it if it was open before the extension loaded). The top-right overlay reads `Webgd capturable`, `FPS <n>`, `Frame <n>`; it ignores the mouse.
2. Click the webgd action. The Capture tab lists the target with `gpuDevices: 1`. While a capture runs, the overlay shows ` capturing…`.
3. Click **Capture**. Events shows groups `Offscreen`, `Compute`, `Composite`, bold draws, ending with the queue `submit`, plus a collapsed `Pre-frame setup (N calls)` group. Select the last command: Log shows no errors and the status bar shows `Event N / N`.
4. Select `drawIndexed` in `Offscreen`. Render Targets shows the 256×256 rgba16float cube target; API Inspector shows `primitive.topology` `triangle-list` and `depthStencil.format` `depth24plus`, and its stages list group 0 (uniform buffer, texture view, sampler), vertex slot 0 and the uint16 index buffer.
5. Select the `setPipeline` before the draw. The target shows only the clear color. Scrubber: click and Left/Right step the selection; Home/End select the first/last event. Scrubber blocks have distinct colours per action, each with a 3 px kind strip.
6. Geometry tab (Frame Debugger centre group), with `drawIndexed` selected: 36 vertices, 24 unique, 12 primitives. Pre-VS shows the vertex table under `Slot 0 · stride …` with `float32x3` and `float32x2` columns; Post-VS shows `Vertex shader outputs · instance 0` with position `f32x4` and uv. Orbit/pan/zoom work, double-click fits, Wireframe/Solid/Points switch the drawing, and Reset view resets the camera.
7. Resources: open the checker `GPUTexture` (64×64, readout 0 or 255) and the storage buffer as `f32` at end of frame (values follow `sin(i*t)`, entry 0 is 0).
8. Revisions (Resource Viewer, offscreen target texture): the list has a pre-frame `create` row and frame `write` rows for the offscreen pass. Click a frame row: that command is selected and the header reads `Revision r · contents at command #idx`. ← / → jump between writes.
9. Frame start: click the pre-frame `create` row (or a row in the Events `Pre-frame setup` group). The setup call is highlighted, the status bar shows `Pre-frame setup call #k`, and the viewer header reads `contents at frame start`; the checker texture still shows its checkerboard.
10. GPU Trace workspace → **Run trace**: a `Queue (GPUDevice#…)` row with pass bars, `Offscreen` / `Compute` / `Composite` markers, counter rows. Real pass bars and non-zero ALU/occupancy need `--enable-webgpu-developer-features` (or the matching chrome://flags entry). Items bars have the same colour as the same action in the Scrubber. Clicking a draw bar selects it in Events; back in Frame Debugger, Events shows GPU Duration and Scrubber widths follow it.
11. Text export: with the trace from step 10 loaded, **File → Export capture as text (.md)** downloads `capture-<unix-ms>.md` and **Export GPU trace as text (.md)** (or **Export as text** in the GPU Trace panel) downloads `trace-<unix-ms>.md`. Open both in a text editor: the capture file lists the frame commands, resources and draw state, and matches `webgd capture <saved.webgd>` apart from the header lines; the trace file has notes, passes, markers, items, counters and the per-item summary. The trace export stays disabled until a trace of the loaded capture has run.
12. Repeat with `webgl2.html`: the overlay shows; `gl2: 1`, marker groups, `drawElements` shows the RGBA16F target, uniforms and texture units; Geometry Pre-VS shows `aPos` / `aUv` columns and Post-VS shows `gl_Position` and `vUv`; the LUMINANCE texture is viewable; the depth renderbuffer shows the not-captured banner; Trace shows the sequential-layout note and `Fragments (rasterized, pre-depth)`. A page that only creates a WebGL1 context shows `Webgd: WebGL1 not supported` in the overlay.
13. **File → Save .webgd**, serve `python3 -m http.server 8080 --directory extension/ui`, open `http://localhost:8080`: the Capture panel shows `standalone mode: live capture unavailable`; **File → Open .webgd…** with the saved file reproduces steps 3–9.

## Automated browser testing

- Branded Chrome ignores `--load-extension`. Launch with `--remote-debugging-port=<port> --enable-unsafe-extension-debugging` and load the extension over CDP with `Extensions.loadUnpacked` (`path` = absolute path to `extension/`).
- Use a fresh `--user-data-dir`.
- Pass `--disable-backgrounding-occluded-windows` (and keep the target tab visible). Open the target page and the webgd UI in separate windows so the target's `requestAnimationFrame` keeps running; otherwise capture fails with `target does not render with requestAnimationFrame`.
- Add `--enable-webgpu-developer-features` for unquantized WebGPU timestamps.
- Open the target page after the extension is loaded, then open `chrome-extension://<id>/ui/index.html`.

## Adding support for an API method

1. **Capture** (`extension/hook.js`). Methods on the wrapped prototypes are recorded automatically during capture. If the call creates or configures an object that must exist before the frame, mark it as tracked so it goes into the setup log: WebGL2 methods via `GL_TRACKED` (plus every `create*`/`delete*`), WebGPU methods by setting `s.tracked = true` in the per-class `switch` that builds each method's wrapping spec. If it needs pre-frame contents, extend the snapshot code. New wire record or value kinds need matching changes in `wire.rs` and the fixture (see Fixture rule).
2. **Replay** (`crates/webgd-replay/src/engine.rs`). `Engine::dispatch` handles `webgd:*` pseudo-methods first, then special cases matched on `(class, method)`; everything else goes through the generic `invoke`, which calls the method by name and maps an object result to its id. Add a special case only when the replay device needs different arguments or behavior (feature/limit clamping, usage augmentation, canvas contexts, mapped ranges). Snapshot application lives in `gl/snapshot.rs` and `gpu/snapshot.rs`. All JS access goes through `js.rs` helpers, not web-sys WebGL/WebGPU bindings.
3. **Command kind** (`crates/webgd-core/src/track/commands.rs`). Classify new draw/dispatch/clear/copy calls so they render bold and appear as trace items.
4. **Inspection** (`gl/inspect.rs`, `gpu/inspect.rs`, `webgd-core::track::{gl,gpu}`) if the call changes bound state.
5. **Trace** (`trace.rs`) if the call is a new item type that needs timing or invocation counts.
6. **Label**: `display.rs::call_label` formats arguments generically; change it only for new value kinds.

## Conventions

- Rust everywhere except the three extension scripts, which must be JS (synchronous `document_start` patching and extension APIs).
- Pure logic goes in `webgd-core` / `webgd-analysis` with native tests; wasm crates contain browser glue only.
- Replay never aborts on a JS exception: the error is recorded with its frame index (setup/snapshot errors use `usize::MAX`, prefixed with the section) and replay continues.
- Hook-internal API use calls the saved original functions so it is never recorded.
- Every estimated value is labelled `(est.)`; all cost constants live in `crates/webgd-analysis/src/model.rs`.
- No inline scripts in `web/index.html` (extension CSP).
- Keep `cargo clippy` clean on the wasm crates.
