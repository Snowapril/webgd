webgd

An in-browser frame debugger for web pages that use WebGL2 or WebGPU. It is a Chrome MV3 extension plus a Rust/WASM egui UI. It captures one frame, replays it on webgd's own device up to any command, and shows render targets, pipeline state, bindings, resource contents and an estimated GPU trace.

Features

Frame capture

Every WebGL2/WebGPU call in one requestAnimationFrame frame, plus a frame-start snapshot of resource contents and state.

Events and scrubber

Events panel with #, kind strip, label and GPU Duration columns, Actions only, collapse/expand, filter and a selectable Pre-frame setup group. A scrubber strip of actions sized by GPU duration after a trace.

API Inspector

Selecting an event replays to it. Stage list (Input Assembly, Vertex Shader, Rasterizer, Fragment Shader, Depth/Stencil, Color Output, or Compute Shader / Dispatch) with resource links, plus Render Targets with thumbnails and a large preview.

Resource browser

Resources table with Origin, Revisions and Last write columns. Texture viewer (mip/layer, channels, range/Auto, zoom/pan, texel readout), buffer viewer (hex/u8/u16/u32/i32/f32/f16), shaders, programs, descriptor trees, and a per-resource revision history.

GPU trace

Timeline with collapsible queue groups and a counters group (Occupancy, ALU, Branches, Texture samples, all "(est.)", and Fragments), crosshair, adaptive ruler and range selection with a Range summary.

Save / open

.webgd files are the raw wire bytes. A standalone mode opens them without the extension.

Geometry tab

Pre-VS / Post-VS view of the selected draw (Wireframe / Solid / Points, position source, Clip space (no divide), instance selector, orbit/pan/zoom, double-click fit, NDC clip box) with a vertex table grouped by layout slot. WebGPU post-VS runs the vertex entry as a compute shader; WebGL2 uses transform feedback. executeBundles, multiDraw and GL base instance ≠ 0 are unsupported; failures appear as the Post-VS disabled reason.

Page overlay and event colours

Pages with a WebGL2 context or GPUDevice show Webgd capturable, FPS, frame count and capturing… in a click-through top-right overlay (WebGL1-only pages: Webgd: WebGL1 not supported); it is never recorded. Each action gets a distinct golden-angle hue, shared by Scrubber blocks and Trace Items bars, with a 3 px kind strip.

Architecture

Details: architecture.md and the byte-level format in wire-format.md.

Capture, replay, inspect

  1. Arm. The UI sends capture; bridge.js forwards arm to hook.js.
  2. Snapshot. On the next rAF callback hook.js records pre-frame resource contents and GL state.
  3. Record. Every call until the next rAF timestamp is recorded, then encoded as wire bytes.
  4. Transfer. bridge.js sends base64 chunks; port.rs reassembles and wire::decode builds a Capture.
  5. Replay. webgd-replay runs setup, snapshot and frame up to the selected command on fresh contexts/devices.
  6. Inspect. Targets, pipeline, bindings and resources are read back from the replay state; the trace runs instrumented replays.

UI and revision history

Workspaces. A top menu bar has File (Open .webgd…, Save .webgd; Ctrl/Cmd+O), Capture (Refresh targets, Show Capture panel, one entry per live target with gl2/gpu counts) and Window (focus any tab). It also switches between the Frame Debugger and GPU Trace workspaces, and each one keeps its own dock layout. The bottom status bar shows the source URL, the position (Event i / N, Pre-frame setup call #k, Frame start, Frame end), replay status and an error count that opens the Log when clicked. Home/End select the first or last event.

Panels. Events, Scrubber (click/drag to select, Left/Right to step), API Inspector, Render Targets (Fit / 1:1, Open in Resource Viewer, texel readout), Resources (Written in frame toggle; double-click selects the last write), Resource Viewer, GPU Trace, and Log (Errors/Warnings/Notes chips and a filter; clicking an error row selects its command).

Revision click-through. webgd_core::track::revisions (all, revision_at, Revision, Access) lists every create/write/read/destroy access to a resource in the pre-frame and frame sections. The Resource Viewer shows them in a Revisions side panel (Rev, Section, Event, Access, Call, detail). Clicking a frame revision selects that command. Clicking a pre-frame revision selects the setup call and shows the contents at frame start, using Replayer::replay_to_frame_start. ← / → jump between writes. The header reads Revision r · contents at command #idx or contents at frame start.

Trace range summary. Drag on the ruler, or shift+drag, to select a time range. Esc clears it, and Zoom to range / Clear range act on it. The Range summary shows the duration, the item count, the average and total for each counter, and the 10 longest items. Clicking one of them selects its command.

Known limitations

  • Counters are estimates from a static cost model. Timing is measured on webgd's replay device, not the page's own submission.
  • Chrome quantizes WebGPU timestamps (about 65 µs) unless chrome://flags/#enable-webgpu-developer-features is enabled.
  • WebGPU occlusion results in Chrome are 0/1 visibility flags, so Fragments (post-depth) is 0 or 1.
  • Passes with render bundles or occlusion queries are timed whole ("unsplit pass"). Independent WebGPU passes may show overlapping timestamps (GPU concurrency).
  • depth24plus textures are not viewable. Pre-frame depth/stencil and MSAA contents are not captured (shown as a banner).
  • GL errors are reported once per section.
  • WebGL1 is detected but unsupported. Workers and OffscreenCanvas in workers are unsupported.
  • Capture needs a visible tab driven by requestAnimationFrame; otherwise: target does not render with requestAnimationFrame.
  • Each replayed requestAdapter gets a fresh adapter.

Quick start

Requires Rust 1.99+ (edition 2024), Node, and Chrome 121 or newer.

rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.130 --locked
cargo xtask build
python3 -m http.server 8000 --directory tests/pages

Open chrome://extensions, enable Developer mode, Load unpacked, select extension/. Reload pages opened before install, open http://localhost:8000/webgpu.html or webgl2.html, then click the webgd toolbar action. Standalone UI (no live capture): python3 -m http.server 8080 --directory extension/ui. More in user-guide.md and development.md.
